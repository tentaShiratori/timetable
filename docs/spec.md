# Timetable 仕様書

実装のチェックリストは [todo.md](./todo.md)。

## 概要

曜日ごとの予定を、Google カレンダーの週表示に近いグリッド上で編集・閲覧する Android アプリ。

実カレンダーと違い、日付は進まない。画面は常に「月曜〜日曜」の枠として固定し、授業・シフト・ルーティンなどの繰り返し時間割として使う。特定の年月日には紐づけない。

配布・動作対象は Android のみ。Windows / macOS / Linux のデスクトップと iOS は対象外。

## 現状スコープ

- 週グリッド表示（左に時刻軸、横に月〜日）
- 予定の追加・編集・削除
- 予定は「複数曜日 + 開始時刻 + 終了時刻 + タイトル」で持つ（1 件の予定を複数曜日に表示できる）
- 予定ごとの todo リスト（チェックは 24 時間で自動リセット。予定 1 件で共有）
- 予定の重なりは許可する（見た目で重なって表示する）
- ローカル保存（アプリ再起動後も復元）
- ホーム画面ウィジェットで週グリッドを常時表示（閲覧のみ）
- 予定の 10 分前に OS 通知（選んだ曜日ごとに毎週同じ時刻）

### 対象外（将来）

- 年月日から進むカレンダー（週送り・今日へジャンプなど）
- 月表示・日表示
- Google カレンダー連携・クラウド同期
- 予定ごとのリマインド ON/OFF や「何分前か」の変更
- 日付で数える繰り返し（隔週・毎月など）。隔日は曜日の組み合わせ（例: 月・水・金）で表す
- 過去の時間割の履歴・バージョン切り替え（必要になったら追加する）
- デスクトップ（Windows / macOS / Linux）および iOS 向けの配布・最適化

## 画面構成

スマートフォンの縦画面を前提にする。週グリッドの描画方針は [tech-decisions/calendar-display.md](./tech-decisions/calendar-display.md) を参照。

- **週表示（メイン）**
  - 列: 月・火・水・木・金・土・日
  - 行: 時刻（表示は 6:00〜24:00、30 分刻み）
  - 予定は `toOccurrences` で曜日ごとのコマに展開し、開始〜終了の矩形としてセル上に置く
  - コマをタップすると元の予定の詳細画面を開く
- **予定の詳細**（`/event/{id}`）
  - 既存の予定をタップして開く
  - タイトル、曜日と時刻、メモ、todo のチェックリストを表示
  - チェックの切り替えはその場で保存する。外したら `completedAt` を消す
  - todo が 1 件以上あるとき、リストの下に「チェックをリセット」を出す。押すとその予定の todo 全部から `completedAt` を消し、その場で保存する（確認ダイアログは出さない）。チェックが無いときは disabled。todo が 0 件ならボタン自体を出さない
  - やることは予定 1 件で共有する（どの曜日のコマから開いても同じ）
  - 「編集」で編集画面へ、「戻る」で週表示へ
- **予定の編集**（既存は `/event/{id}/edit`、新規は `/event/new/{dow}/{start}`）
  - 空き時間をタップして新規作成。そのマスの曜日だけが最初から選ばれている
  - 詳細の「編集」から開く
  - 入力項目: タイトル、曜日（複数選択。平日 / 土日 / 毎日のまとめボタンあり）、開始時刻、終了時刻、メモ（任意）、todo（追加・名前変更・削除）
  - 曜日を 1 つも選ばないと保存できない
  - todo の変更は「保存」で確定し、「戻る」なら破棄する
  - 既存の削除後は週表示へ戻る。新規の保存後も週表示へ戻る。既存の保存・戻るは詳細へ戻る
  - 削除は予定単位。選んだ曜日すべてから消える

## ホーム画面ウィジェット

Android のホーム画面に週グリッドを置く。描画方針は [tech-decisions/android-widget.md](./tech-decisions/android-widget.md) を参照。

- アプリ画面と同じ「時刻軸 + 月〜日の 7 列 + 色付きブロック」
- 予定は 30 分スロット単位で表示する（ウィジェットの制約。正確な時刻はアプリで見る）
- `daysOfWeek` を曜日ごとに展開して描画する。古い `dayOfWeek` 形式も読む
- 時刻の範囲はアプリと同じ 6:00〜24:00 固定。入りきらない分は縦スクロールで見る
- タップするとアプリが開く。ウィジェット上での編集はしない
- 内容が更新されるのはアプリを離れたとき。定期更新はしない
- todo はウィジェットに出さない（閲覧対象は予定ブロックのみ）

## データモデル

```
EventTodo {
  id: string
  title: string
  completedAt?: number  // 1970-01-01 からのミリ秒。未完了なら無し
}

Event {
  id: string
  title: string
  daysOfWeek: DayOfWeek[]  // 0 = 日曜 … 6 = 土曜。空不可・重複不可。小さい順に並べて保存
  startMinutes: number  // 0:00 からの分（時刻は 1 組）
  endMinutes: number
  note?: string
  todos?: EventTodo[]
}

Occurrence {
  eventId: string
  dayOfWeek: DayOfWeek
  startMinutes: number
  endMinutes: number
  title: string
}
```

日付（年・月・日）は持たない。`todos` が無い既存データは空リストとして扱う。

古い `dayOfWeek` だけのデータは読み込み時に `daysOfWeek: [dayOfWeek]` へ直す。次に保存するときに新しい形で書き出す。「毎日」で作った既存の 7 件をまとめ直すことはしない。

### 予定ごとの todo

- 予定 1 件でリストを共有する。複数曜日でも同じ todo を見る
- 並びは追加した順。項目名は空にできない。件数の上限はなし
- チェックは項目ごと。`completedAt` から 24 時間以上たった項目は、アプリ起動時とバックグラウンド復帰時に未完了へ戻す（変化があったときだけ保存）
- 判定は純粋関数 `resetExpiredTodos(todos, now)` にまとめる
- 手動でまとめて外すときは `clearTodoCompletions(todos)` を使う（項目は残し、`completedAt` だけ消す）

## 制約

- 終了時刻は開始時刻より後であること
- タイトルは空不可
- 曜日は 1 つ以上。空配列・重複・範囲外は不可
- 1 日の範囲は 0:00〜24:00。日をまたぐ予定は v0.1 では扱わない

## 技術スタック

- Tauri 2（Android） / React 19 / TypeScript / Vite
- パッケージマネージャ: pnpm
- ファイル I/O は Tauri コマンド `load_app_file` / `save_app_file`
- 予定はアプリデータディレクトリの `events.json` に JSON 配列で保存する。起動時に読み込み、追加・更新・削除のたびに全件を書き出す
- 読み込み時に壊れた行（タイトル空、終了 ≤ 開始、曜日不正など）は捨てる
- リマインドは Tauri の notification プラグインで、開始の 10 分前に選んだ曜日ごとに毎週出す。通知 id は予定 id と曜日を組み合わせる。曜日を外した分や消した予定の通知は取り消す。詳細は [tech-decisions/notification.md](./tech-decisions/notification.md)
- 消した予定の通知 id は `cancel` が通るまで `reminder_ids.json` に残す。`cancelAll` は使わない
