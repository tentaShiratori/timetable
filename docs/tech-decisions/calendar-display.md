# カレンダー（週グリッド）の表示方法

- 日付: 2026-08-26
- 状態: 採用（実装済み）
- 対象: [spec.md](../spec.md) の週表示

## 結論

カレンダーライブラリは使わない。CSS Grid で「時刻 × 曜日」の背景を描き、予定は各曜日カラム内に絶対配置する。

スマホ縦画面では **月〜日の 7 列を横スクロールせず 1 画面に収める**。時刻方向だけスクロールする。予定の詳細はブロック上の短いタイトルでは足りないので、タップで編集画面を開く。

## 前提

- Android・縦画面。幅はおおよそ 360px 前後
- 日付は持たない。列は常に月〜日
- 時刻範囲は 6:00〜24:00、30 分刻み
- 予定の重なりは許可する
- 空きマスのタップ / ドラッグで作成、既存予定のタップで編集

Google カレンダーの週表示は「実在する 1 週間」を送る UI である。このアプリは同じ見た目（時刻軸 + 曜日列 + 矩形の予定）だけ借りて、枠は固定の時間割にする。

## スマホで週を出すときの問題

時刻ラベルを約 40px 取ると、残りは約 320px。7 列だと 1 日あたり約 45px。タイトルはほぼ見えない。

それでも週全体を一度に見ることが時間割の本体なので、v0.1 では列を削らない。代わりに次で逃げる。

- ブロックは開始時刻から決めた色 + 1 行省略のタイトル
- 中身はタップ先の編集画面で読む
- 30 分あたりの高さはタップできる大きさ（目安 40px 前後）を固定し、18 時間分は縦スクロールする。6:00〜24:00 を画面内に圧縮しない

曜日ヘッダーは縦スクロール中も画面上部に固定する。今日の曜日だけ丸い印を付ける（週送りや「今日へジャンプ」はしない）。

将来、列が狭すぎて使えないと分かったら次を検討する。横スクロールで列幅を確保する、平日 5 列にする、週概要 + 1 日拡大の 2 段にする、など。v0.1 ではやらない。

## 表示の作り方

### 採用: CSS Grid 背景 + 予定の絶対配置

```
[時刻] [月] [火] [水] [木] [金] [土] [日]
 6:00
 6:30
 7:00
  ...
```

- 背景: `grid-template-columns: 時刻列 + 曜日×7`、`grid-template-rows: ヘッダー + 30分マス×36`
- 各曜日カラムは `position: relative`
- 予定の位置は分から計算する  
  `top = (startMinutes - 6:00) / 30 * スロット高さ`  
  `height = (endMinutes - startMinutes) / 30 * スロット高さ`
- 重なりは同一曜日内で横に並べる。幅を分割し、極端に細くなったら重ねて表示してタップで開けるようにする

HTML のマスはヒット領域と罫線のためにある。予定の長さはマス結合ではなく、分単位の座標で決める。9:10〜10:25 のような 30 分に乗らない時間も同じ式で置ける。

### 棄却したもの

**FullCalendar / react-big-calendar / Schedule-X など**

週表示・ドラッグ・重なり処理は揃っているが、すべて「日付のあるカレンダー」が前提。日付を進ませない時間割にすると、ダミー日付や週送りの無効化でライブラリと戦うことになる。バンドルも大きく、スマホ向けの列幅制御もこちらの都合に合わせにくい。

**HTML の table**

罫線は簡単だが、予定をセルにまたがせて重ねるのが苦しい。絶対配置するなら table である必要がない。

**Canvas / SVG でグリッドごと描画**

重なりやドラッグの座標計算はしやすいが、文字・タップ対象・テスト（Testing Library）との相性が悪い。予定ブロックは DOM のままにする。

**1 日表示を主、週はヘッダーだけ**

Google カレンダーの Android アプリに近い。1 日の予定は読みやすいが、時間割として週を見渡す用途とずれる。

## 操作

v0.1 の主経路はタップとする。

- 空きマスをタップ → その曜日・開始時刻を入れた作成画面
- 予定をタップ → 編集・削除
- ドラッグで範囲指定して作成は、誤操作（縦スクロールとの取り合い）が起きやすいので後回し。入れるなら「短押しで開始、閾値以上動いたら作成モード」に限る

ライブラリ（interact.js など）は、ドラッグ作成を本採用してから検討する。

## やらないこと

- 仮想化。7 列 × 28 マス + 予定数十件程度では不要
- 現在時刻ラインや「今日へジャンプ」。日付を進ませない方針と混ぜない
- ピンチズーム、月表示、日表示

## 見直しのきっかけ

- 実機で 7 列がタップ不能 / 読めない
- ドラッグ作成が必須になった
- 履歴や「実日付の週」が仕様に入った（そのときは日付カレンダーライブラリを再評価する）
